Ты выступаешь в роли проектного менеджера и технического писателя.
Твоя задача — выполнить требования к Лабораторной работе №1 "Инициация проекта" для нашего репозитория.

ВАЖНО: Весь создаваемый контент должен быть строго на русском языке.

Создай в корне репозитория 5 Markdown-файлов со следующей структурой и содержанием:

1. Home.md
- Название и краткое описание проекта, цель лабораторной работы (инициация проекта, освоение GitHub).
- Навигация (ссылки на страницы Ideas, Evaluation, Concept, Stakeholders).
- Состав команды: Менеджер проекта (автор репозитория) и 2 эксперта-одногруппника.

2. Ideas.md
Опиши 3 независимые реалистичные идеи для учебного ИТ-проекта (например: мини-скрипт парсинга конспектов в карточки, Telegram-бот для трекинга привычек, сайт-справочник/шпаргалка на GitHub Pages).
Каждая идея ОБЯЗАТЕЛЬНО должна содержать разделы:
- Название идеи
- Потребность (какая проблема решается)
- Основные результаты проекта (ключевая функциональность)
- Потенциальный рынок и целевая аудитория
- Примерные сроки вывода продукта на рынок (MVP и развитие)
- Технологии
- Оценка рисков и технической сложности

3. Evaluation.md
- Таблица мультикритериальной оценки трех идей от трех экспертов (шкала 1-5).
- Критерии и их веса:
  * Потребность — 35%
  * Реализуемость — 30%
  * Оригинальность — 15%
  * Time-to-market — 20%
- Проведи математический расчет взвешенного среднего балла по формуле для каждого эксперта и итоговый средний балл по каждой идее.
- Выдели идею-победителя (с наивысшим баллом), приведи развернутое обоснование выбора и комментарии экспертов.

4. Concept.md
Оформи концепцию выбранной идеи:
- Концепция: Проблема, Решение, Целевая аудитория, Ключевой результат.
- Цель проекта, сформулированная строго по критериям SMART (с конкретными метриками и сроками).
- Раздел «Устав проекта»: Название, Менеджер, Заказчик, Сроки (MVP / релиз), Ориентировочный бюджет.
- Раздел «Классификация и ограничения»:
  * Классификация по 6 принципам (масштаб, сложность, сроки, класс, вид, тип).
  * Ограничения по проектному треугольнику (Объем — Сроки — Стоимость) с указанием приоритетного ограничения.
  * Выбор методологии управления (Agile/Scrum, PMBOK или Гибрид) с аргументацией.
- Раздел «Экономика проекта»:
  * Расчет точки безубыточности x = a / (s - b), где a — фиксированные расходы, s — цена, b — переменные расходы на единицу.
  * Расчет NPV проекта на горизонте 2-3 года по формуле NPV = sum(CF_t / (1 + r)^t) - I_0 со ставкой дисконтирования r = 15-20%.
  * Экономический вывод (достижимость безубыточности, положительность NPV).

5. Stakeholders.md
- Реестр заинтересованных сторон (6-7 сторон: Команда разработки, Пользователи, Заказчик/Инвестор, Регуляторы/Площадки дистрибуции, Внешние API-сервисы и т.д.).
- Для каждой стороны укажи: Роль и интерес, Влияние (высокое/среднее/низкое), Стратегию взаимодействия.
- Матрица «Интерес / Влияние» в виде Markdown-таблицы 2x2 с распределением сторон по квадрантам.

Оформи все файлы аккуратно, используя валидный синтаксис Markdown (заголовки, списки, таблицы). Все математические вычисления должны быть точными.
